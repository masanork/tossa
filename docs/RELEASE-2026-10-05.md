## 管理者メール通知と復元演習の追加対応

ユーザーの「go forward」と、障害時の通知先は管理者アカウントのメールでよいという方針に基づき、次を追加した。

- 現在の管理者の確認済みメールへ、画面/API、バックアップ、保守・一覧更新、書込・通知Queueの失敗を通知する。通知時に現在の役割とアドレスを照会し、BCCで宛先を隠す。本文は発生元・検出時刻・確認先に限定する。同じ発生元はD1で5分間抑制し、送信の全部または一部の失敗時は1分へ短縮する。次の失敗検知時に再試行する仕組みで、独立した再送ジョブではない。
- 管理画面に通知先の設定状態を追加した。照会失敗は未設定と区別し、通知状態の照会だけが失敗してもR2のバックアップ一覧は表示する。設定済み表示はメール着信の証明ではない。
- Queue内で個別に処理された失敗も集約して通知する。Pushの404/410は期限切れとして削除・完了扱いにし、それ以外の失敗は再試行する。定期一覧更新はKV保存失敗をCron側へ伝える。
- 復元SQLで長い文字列を24KiBずつ一時BLOBへ組み立て、完成した行を一度に挿入する。主キー・外部キー・NUL・UTF-8を保ち、SQL文は64KiB以内にする。約190KBの単一文字列も復元した。
- `npm run backup:drill` を追加し、CIにも組み込んだ。隔離したローカルWorker/D1/R2で実際の保存・復元を行う。6,261,970バイトを2パート（5,242,880 / 1,019,090バイト）で保存し、17表の件数、150投稿の文字列バイト、NULL、外部キー、整合性、一時表の除去、リース解除が一致した。復元SQLの最大文長は49,240バイト。本番データを使った演習ではない。
- 実際の管理者2人による読み取り専用の運用検査 `npm run smoke:admin` と45分の地域試用手順を用意した。トークンを引数・ファイル・出力へ載せず、異なる管理者の権限、バックアップ鮮度、報告閲覧、通知設定を確認する。担当者・地域・参加者が未指定のため本番での2人検査と地域試用は未実施。
