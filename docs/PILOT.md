### PWA更新の確認順

1. 更新前のPWAで通信を切り、訓練用と明示した投稿を未送信欄へ保存する。入力中の下書きも別に用意する。
2. 通信を戻し、PWAを開いたまま更新を取得する。入力中の画面が勝手に再起動せず、下書きと未送信データが残ることを確認する。
3. 下書きを保存し、同じサイトのブラウザータブとPWAの全画面を閉じる。新しい版は全画面を閉じた後に有効になる。PWAアイコンを削除したり、サイトの保存領域を消去したりしない。
4. PWAを再び開いてから通信を切り、一覧・投稿画面・未送信欄が開くことを確認する。通信を戻し、投稿が一件だけ反映されることを確認する。

更新の途中で通信が切れた場合も、以前の画面を開けることを確認する。この手順のブラウザー自動検証と、ホーム画面からの実機起動・OSによる保存領域の保持は別に記録する。

## 参加者に依頼する三つの作業

### 開始前と45分の進め方

地域と実施日を決め、利用者3〜5人、管理者、代替担当者を記録する。管理者と代替担当者はそれぞれのアカウントでPasskeyログインとメールアドレスの確認を済ませる。[管理者の読み取り検査](OPERATIONS.md#管理者代替担当者の読み取り検査)で権限と保存実績を確認してから開始する。画面を見ながら操作を観察する担当者を一人決める。

| 時間     | 作業                                         | 記録                                   |
| -------- | -------------------------------------------- | -------------------------------------- |
| 0〜5分   | 地域・端末・担当を確認し、訓練データを説明   | 端末・OS・起動方法・PWA版              |
| 5〜15分  | 周辺の情報を探し、距離と古さを説明してもらう | 到達時間・迷った箇所・理解の違い       |
| 15〜25分 | 訓練投稿を作り、状態を更新する               | 観測時刻・確認表示の理解・操作時間     |
| 25〜35分 | 通信を切って保存し、閉じて再起動、通信復帰   | 未送信件数・写真・反映件数・保存エラー |
| 35〜45分 | 管理者が報告を処理し、全員で振り返る         | 未対応報告・担当負担・優先する改善     |

運営担当者は訓練投稿のIDを控え、終了後に対象だけを削除する。アカウントやサイトデータ全体を消去しない。問題が起きたときの連絡担当は管理者、引き継ぎ先は代替担当者としておく。

### 当日の操作

1. 現在地周辺の必要な情報を探す。検索・分類・距離順・地図を使い、到達時間と迷った箇所を記録する。距離表示は直線距離なので経路の実測とは分ける。
2. 施設の状態を更新する。観測時刻、運営確認、利用者の確認、古さの表示を本人の言葉で説明してもらい、誤解を記録する。別端末で同時更新した場合の保留も確認する。
3. 通信を切って投稿し、アプリを閉じて開き直し、通信を戻す。未送信表示が理解できるか、投稿が一度だけ反映されるか、保存できない場合に下書きが残るかを確認する。

運営担当者は問題報告を一件受け、必要な編集と対応結果の記録を行う。訓練投稿は訓練用と明示し、一般公開の実在施設の状態を書き換えない。

## 保存・競合・運用の追加確認

保存領域の破損や容量不足を意図的に起こす試験は、訓練データだけの隔離環境で行う。既存の未送信データが入った端末では再現操作をしない。

1. 同じサイトを二つのタブで開き、通信を切って両方から別の訓練投稿を保存する。両タブの未送信表示に二件残ること、一方で破棄するともう一方の表示も変わることを確認する。送信中に別タブで保存した投稿も残ることを確認する。Web Locksが使えない環境でも試す。写真を付けた場合の保存件数・容量と「端末保存の状態」の保護許可を記録する。保護が拒否されても保存を続けられることを確認する。
2. 別端末から同じ訓練投稿を更新した後、古い状態更新を通信復帰時に送る。保留内容と最新内容を確認し、「最新を確認して再入力」から新しい報告を保存する。再入力の取消・保存失敗では元の保留データが残り、保存成功後に元の項目が整理されることを確認する。
3. 容量不足では入力画面を閉じず、入力内容が残ることを確認する。破損検出では元の未送信データを書き出して保全し、回復操作を確認する。エラー表示、回復前後の件数、再送結果を記録する。
4. 管理者はバックアップの最新保存日時、経過時間、合計容量、手動実行の件数と時間を記録する。取得失敗と保存実績なしが違う表示になることを確認する。代替担当者も自分のPasskeyで同じ操作を行う。

旧版からの初回移行では、旧版の画面を残したまま新版を開き、端末保存が一時停止し、旧原本を消さないことを確認する。全画面を閉じて新版を開き直した後、操作IDと件数を保った移行・再送を確認する。写真を含む未送信データの書き出しファイルは、本人だけがアクセスできる場所に保存する。

## 判断と次の改善

投稿の消失・他人のアカウントへのキー追加・非公開情報の露出・古い更新による上書きは試用を止めて修正する。検索や画面の理解が難しい場合は、完了時間、誤操作、質問内容を使って導線と説明を改める。

試用後に未送信/競合の件数、報告の処理時間、情報確認の担当負担を振り返る。各課題について「再現条件・影響・担当・次の確認方法」を一行で残し、[ロードマップ](ROADMAP.md)を更新する。
