## 外部通知と実データ復元の追加対応

ユーザーの継続指示に基づき、同じチームで次を追加した。

- 外部監視は全宛先のAPI受理後にだけ障害のfingerprintと時刻を保存する。同じ異常条件を30分間抑制し、新規条件・継続30分・正常復帰を通知する。復旧通知の受理後に状態を解除する。未設定・dry-run・送信失敗では受理済み状態を更新しない。
- GitHub Actionsは秘密や宛先を含まない状態JSONだけをcacheで引き継ぐ。状態更新のあった失敗ジョブでも保存する。cache消失時の重複と、破損状態での5分間隔の汎用通知はありうる。
- 現在の確認済み管理者1人を読み取り、外部監視用のproduction宛先Secretを設定した。アドレスは標準出力・リポジトリ・cacheに含めない。送信tokenは未設定で、実メールは送っていない。
- SQL退避は明示的なAPI tokenでremote操作し、local復元・照合にはCloudflare認証を渡さない。各段階と全体の実測時間を非機密レポートへ残す。D1 export中はクエリ受付が停止しうるため、`--allow-query-outage` を必須にした。本番exportは実行しない。
- 既存の非公開R2 v2アーカイブを明示指定し、一時的なlocal D1へ復元する `backup:production-drill` を追加した。26時間以内・100MiB以下・全17表を検証し、本番D1への問い合わせ・エクスポート・書き込みは行わない。アーカイブ・復元SQL・local DBは非公開の一時領域に置き、終了時に除く。
