# 2026-10-06の規模対策

ユーザーの「go forward」に基づき、負荷測定と公開一覧・通知・書込Queueの改善を実装した。追加のチーム監査は実行上限のため継続できず、司令塔が実装・差分確認・回帰検査を引き継いだ。今回の独立レビューを完了したとは扱わない。

## 変更

- KV公開フィードの更新を既存の書込Queueへ集約し、consumerの並列数を1に制限する。同一バッチの更新要求は一つにまとめる。公開保存失敗は更新ジョブを再試行し、コミット済み投稿は公開失敗だけで再書き込みしない。直近の更新で公開を省略した場合も3秒後の更新要求を残す。
- 毎分Cronを追加し、120秒以内のKVスナップショットを採用する。未来時刻は採用しない。本番の公開GETでは更新要求を投入せず、閲覧集中で書込Queueを埋めない。管理画面は更新受付と更新完了を区別する。KV伝播・公開キャッシュ・Queue滞留があるため120秒は画面反映の保証ではない。
- 一斉Pushは対象の上限IDとジョブだけを受付時に確保し、Queueで最大100件ずつ読み出して個別配信と後続ページへ渡す。地域・通知種別・除外ユーザーをSQLで選ぶ。旧形式の配信ジョブにも対応する。再配送で同じ通知タグを再利用するが、送信が一度だけになる保証ではない。受付画面を「送信完了」と表示しない。
- Workers observabilityを有効にし、10%サンプリングする。既存DBのスキーマや追加のCloudflareリソースは変更しない。
- `npm run load:local` を追加。隔離したlocal workerd・SQLite・KVと合成投稿で、公開一覧・冷えたD1一覧・文字検索・タグ・bbox・近傍・深いページを分けて実際のAPIを測る。CIでも5千投稿・並列4・各30リクエストで経路と応答を検査し、JSON結果を7日保存する。速度の恣意的なしきい値は置かない。
- 管理画面と文書にあった件数だけからの同時利用者数・D1上限・追加費用なしの判断を訂正した。[規模と負荷測定](capacity.md)に次の順序を記録した。
